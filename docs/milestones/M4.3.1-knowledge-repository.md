# M4.3.1 — Knowledge Repository Abstraction

## Objetivo

Criar o contrato estável do futuro Knowledge Engine sem acoplar regras de negócio a SQLite, FTS5 ou bancos vetoriais.

## Arquitetura

```text
Runtime / Planner / Prompt Builder
              |
      KnowledgeService
              |
    KnowledgeRepository
              |
  implementação registrada no Container
```

## Componentes

- `KnowledgeDocument`: unidade de conhecimento independente do backend.
- `KnowledgeChunk`: trecho indexável de um documento.
- `KnowledgeTag`: etiqueta normalizada.
- `KnowledgeResult`: resultado ranqueado de uma busca.
- `KnowledgeRepository`: contrato para persistência, consulta e documentos relacionados.
- `KnowledgeService`: validação e regras de negócio.
- `Container.register_knowledge_repository`: ponto de composição para backends concretos.

## Decisões

1. Nenhum SQL foi incluído nesta etapa.
2. O serviço depende apenas da abstração `KnowledgeRepository`.
3. A implementação concreta deve ser registrada no `Container`.
4. A ausência de backend gera `KnowledgeRepositoryNotConfiguredError` de forma explícita.
5. Os testes usam `FakeKnowledgeRepository`, permitindo testar consumidores sem banco de dados.

## Preparação para M4.4

A M4.4 implementará `SQLiteKnowledgeRepository`, com busca textual e FTS5 quando disponível, sem modificar o contrato do serviço nem os consumidores futuros.
