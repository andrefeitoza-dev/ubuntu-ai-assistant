# M5.5 — Semantic Knowledge / Local RAG

## Objetivo

Adicionar recuperação semântica local ao Knowledge Engine sem depender de serviços externos ou de um banco vetorial pesado.

## Arquitetura

```text
Knowledge Engine (SQLite + FTS5)
          │
          ├── busca lexical
          │
          ▼
SemanticKnowledgeService
          ├── LocalHashEmbedder
          ├── SQLiteSemanticRepository
          ├── ranking híbrido lexical + semântico
          └── RAGContextBuilder
                         │
                         ▼
                     AIPlanner
```

## Decisões

- Os embeddings são determinísticos e executados totalmente offline.
- O algoritmo usa hashing assinado de unigramas e bigramas em 256 dimensões.
- Os vetores são persistidos no mesmo `knowledge.db`.
- O ranking combina 35% de relevância lexical e 65% de similaridade semântica.
- O índice é sincronizado automaticamente quando documentos ou trechos mudam.
- O Planner recebe trechos, fonte e pontuação; o RAG não autoriza execução.
- A interface `SemanticRepository` permite substituir futuramente o backend por Ollama embeddings, FAISS ou outro mecanismo.

## Componentes

- `LocalHashEmbedder`
- `SemanticRepository`
- `SQLiteSemanticRepository`
- `SemanticKnowledgeService`
- `RAGContextBuilder`
- `SemanticMatch`
- `RetrievalContext`

## Segurança

O conteúdo recuperado é apenas contexto. Confirmação, Reflection, Execution Intelligence e políticas de execução continuam sendo as autoridades de segurança.
