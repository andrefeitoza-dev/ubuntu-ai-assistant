# M5.7 — Agent Loop

## Objetivo

Adicionar um ciclo iterativo de planejamento, confirmação, execução, observação e replanejamento sem remover as barreiras de segurança existentes.

## Componentes

- `AgentLoopController`: máquina de estados e orquestração das iterações.
- `AgentReplanner`: cria uma nova solicitação usando o objetivo original e as evidências da falha.
- `LoopWatchdog`: interrompe repetições sem progresso.
- `AgentLoopConfig`: limites de iteração e estagnação.
- `LoopSnapshot`, `IterationRecord` e `LoopEvent`: estado observável e histórico do ciclo.

## Segurança

Cada plano novo entra em `WAITING_CONFIRMATION`. O controlador nunca confirma automaticamente uma nova iteração. Resultados bloqueados encerram o ciclo imediatamente e não são replanejados para contornar políticas, preflight ou reflexão.

## Estados

`IDLE -> PLANNING -> WAITING_CONFIRMATION -> EXECUTING`

Após a execução:

- sucesso: `COMPLETED`;
- bloqueio: `BLOCKED`;
- falha recuperável: `REPLANNING -> PLANNING -> WAITING_CONFIRMATION`;
- ausência de progresso ou limite: `FAILED`;
- cancelamento: `CANCELLED`.

## Configuração

- `agent_loop_max_iterations` (padrão: 5)
- `agent_loop_max_stalled_iterations` (padrão: 2)

## Uso

```python
controller = container.agent_loop_controller()
snapshot = controller.start("Instalar e habilitar Docker")

# Mostrar snapshot.pending_plan.message e solicitar confirmação ao usuário.
while snapshot.requires_confirmation:
    snapshot = controller.confirm()
```

A aplicação cliente deve solicitar consentimento real antes de cada chamada a `confirm()`.
