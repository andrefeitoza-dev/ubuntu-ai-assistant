# M5.4 — Self Reflection

## Objetivo

Adicionar reflexão determinística antes e depois da execução sem permitir que o agente contorne confirmação, preflight ou políticas de segurança.

## Componentes

- `ReflectionAnalyzer`: regras para coerência, redundância, risco e diagnóstico.
- `ReflectionService`: API de aplicação para reflexão.
- `ReflectionEngine`: fachada consumida pelo runtime.
- `ReflectionReport` e `ReflectionFinding`: resultados estruturados e auditáveis.

## Fluxo

1. O pipeline produz o plano.
2. O runtime reflete sobre o plano e apresenta as observações no preview.
3. Achados críticos bloqueiam a execução, mesmo após confirmação.
4. Cada resultado executado ou bloqueado recebe reflexão pós-execução.
5. A reflexão é registrada no histórico da sessão; o Learning Engine continua registrando o resultado real.

## Regras iniciais

- plano vazio ou etapa sem comando: crítico;
- comando destrutivo classificado como baixo risco: crítico;
- comandos duplicados: aviso;
- ferramenta não selecionada: aviso;
- retorno 126/127: diagnóstico crítico de comando indisponível ou não executável.

## Decisões

- A primeira versão é baseada em regras, rápida, testável e independente de LLM.
- Reflexão não autoriza execução e não substitui o Execution Intelligence.
- Relatórios são imutáveis e expostos pelo `AgentRuntime` para interfaces futuras.
