# Ubuntu AI Assistant v1.3 — Validação de desempenho

## Objetivo

Demonstrar que o assistente seleciona a estratégia mais econômica antes de
usar o modelo de linguagem, mantendo segurança e capacidade conversacional.

## Hardware de referência

- CPU: Intel Core i5-6200U 2.30 GHz;
- núcleos: 2 físicos, 4 threads;
- memória: 7,7 GiB;
- GPU: Intel HD Graphics 520, não utilizada pelo Ollama;
- modelo: `qwen2.5:3b`, 2,2 GB, execução 100% CPU;
- contexto: 4096 tokens;
- sistema com swap ativa.

Esse equipamento representa um cenário limitado e não um supercomputador.

## Procedimento reproduzível

Com o modelo descarregado, executar:

```bash
ollama stop qwen2.5:3b
ubuntu-ai benchmark-routes --include-chat
```

Repetir o comando sem parar o modelo para observar o comportamento aquecido.

## Rotas avaliadas

| Rota | Uso do Ollama | Comportamento esperado |
|---|---:|---|
| Local | Não | microssegundos ou poucos milissegundos |
| Ação segura conhecida | Não | roteamento rápido e execução auditável |
| Chat frio | Sim | maior latência pelo carregamento do modelo |
| Chat aquecido | Sim | menor latência com modelo residente |

## Cenários da apresentação

1. `que dia é hoje?` — resposta local;
2. `mostre a arquitetura das pastas` — Fast Path adaptativo;
3. `mostre os prosessos` — tolerância a erro de digitação;
4. `o que é Docker?` — conversa, sem instalação acidental;
5. `qual é a capital de Portugal?` e uma pergunta de continuidade — memória;
6. `instale o Docker` — ação sensível com confirmação;
7. cancelamento seguido de nova solicitação — recuperação segura.

## Garantias preservadas

- somente planos `LOW` podem ser autoexecutados;
- similaridade não reduz risco;
- aprendizado exige sucesso e feedback positivo;
- falhas e bloqueios impedem promoção do padrão;
- perguntas conversacionais não executam comandos.

## Resultados no equipamento do TCC

Equipamento: Intel Core i5-6200U, 4 threads, 7,7 GiB de RAM e Ollama executado em CPU.

| Cenário | Tempo | Uso do Ollama |
|---|---:|---|
| Resposta local | 217 µs | Não |
| Ação segura | 4,1 ms | Não |
| Classificação para chat | 17 µs | Não |
| IA com cold start | 23,93 s | Sim |
| IA com modelo aquecido | 12,02 s | Sim |
| Configuração pela rota incorreta | 15,78 s | Sim |
| Configuração após correção | 200,3 ms | Não |

A consulta de configuração ficou aproximadamente 78 vezes mais rápida,
com redução de cerca de 98,7% no tempo de resposta.

O resultado confirma que consultas conhecidas do ambiente devem usar o
Fast Path local, reservando o Ollama para interpretação e conversação.
